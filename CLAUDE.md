# funkwhale-v2-deploy

Three ways to deploy Funkwhale 2.0.x: `docker/` (Compose + Caddy, one command), `ansible/` (role), and bare-metal `scripts/` + `config/` templates. No test suite; see Testing.

## Commands

```bash
shellcheck -x -P scripts scripts/*.sh docker/funkwhale.sh
cd ansible && uvx --from ansible ansible-playbook --syntax-check -i inventory.example playbook.yml
```

`--from ansible` (not `ansible-core`) is needed: the role uses `community.postgresql`.

## Architecture

- `scripts/lib.sh` is sourced by `upgrade.sh` and `migrate-v1-to-v2.sh` (both run as root on the host). `funkwhale-updater.sh` is standalone because it can also drive a remote host over SSH (`SSH_HOST`); every command goes through `run_cmd_sudo` (scripts/funkwhale-updater.sh:65) as one `bash -c` string so redirects run as root.
- `config/systemd/` is the single source for units: the scripts and the Ansible role (`tasks/services.yml`) both install from it, replacing `/srv/funkwhale` with the install path.
- nginx exists twice: `config/nginx/funkwhale.conf` and `ansible/roles/funkwhale/templates/funkwhale_nginx.conf.j2`. Change both.
- All three bare-metal scripts share `backups/.rollback_info` and `.installed_version`, so any of them can roll back another's upgrade.
- Docker data lives in `docker/data/` (bind mounts); `.env` is generated by `funkwhale.sh init`, never committed.

## Testing

No automated tests. What was used to verify changes:
- Bare-metal scripts: run functions from `lib.sh` in a sandbox with `FUNKWHALE_DIR`, `SYSTEMD_DIR`, `NGINX_DIR`, `ARTIFACTS_URL` overridden, stub `systemctl`/`nginx`/`sudo`/`pg_dump` on `PATH`, and a local HTTP server serving fake api/front zips (good zip, 404, HTML-as-200).
- nginx configs: `nginx -t -p <dir> -c <wrapper.conf>` with a self-signed cert substituted for the Let's Encrypt paths.
- Docker: copy `docker/` to a temp dir and run `init --domain localhost --project <name>` with `CADDY_HTTP_PORT`/`CADDY_HTTPS_PORT` set to free ports. Caddy issues a local cert for `localhost`. Test `upgrade`/`rollback` by `init --version` one release back.
- Containers write root-owned files into `data/`; delete them from a container (`docker run --rm -v ...:/t alpine rm -rf ...`), not with sudo.

## Gotchas

- `dev.funkwhale.audio` (GitLab) goes down for hours. Bare-metal installs need it for release zips; Docker only needs Docker Hub. `funkwhale-updater.sh` falls back to Docker Hub tags for listing versions (scripts/funkwhale-updater.sh:125). Upstream deploy files are not mirrored on GitHub or Codeberg; read them out of the `funkwhale/api` and `funkwhale/front` images instead.
- Funkwhale 2.0.11 needs Python >= 3.12: Debian 12 and Ubuntu 22.04 can't run it bare-metal. Checked from the release's `pyproject.toml` before anything changes (scripts/lib.sh:130).
- `funkwhale-manage createsuperuser` is refused by 2.0.x; use `fw users create --superuser`. It needs `--email`, and prompts (and aborts without a TTY) unless `--password` is given.
- Usernames `admin`, `root`, `test`, `owner`, `staff` and others are reserved (`ACCOUNT_USERNAME_BLACKLIST` in the API settings). Defaults use the email's local part instead.
- Rollback must drop and recreate the database before `pg_restore`; `--clean` fails when newer migrations added constraints the dump doesn't know (scripts/lib.sh:357, docker/funkwhale.sh:352).
- Django's CSRF trusted origins are `https://<host>` for each allowed host, without a port. A non-443 HTTPS port breaks logins unless `DJANGO_ALLOWED_HOSTS` includes `host:port` (docker/funkwhale.sh:216).
- The front container doesn't serve `/staticfiles/`; Caddy does (docker/Caddyfile:9). Any other reverse proxy must too.
- `curl` without `-f` saves error pages as the download. Every download must use `-f` and be verified before the live install is touched (`fetch_release`, scripts/lib.sh:96).
- `listen ... http2` is kept on purpose: the `http2 on;` replacement breaks nginx 1.22 (Debian 12).
- Docker images also come as `-legacycpu` for amd64 CPUs without AVX2; `init` auto-detects (docker/funkwhale.sh:85) and `upgrade` keeps the suffix.
- The `funkwhale/front` image proxies `X-Forwarded-Proto/Host` from the outer proxy, so whatever terminates TLS must set them (Caddy does by default).
